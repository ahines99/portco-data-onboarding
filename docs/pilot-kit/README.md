# Local operator pilot kit

This kit is ready for preparation. No participant, consent, completed pilot or measured benefit
is represented. Use it with the [pilot protocol](../OPERATOR-PILOT.md), which defines consent,
measurement and sharing rules. Hosting remains free-only; no cloud account is needed.

**The session coordinator starts here.**

1. Read the [participant brief](participant-brief.md). Identify an independent operator and a
   separate reviewer with the required domain knowledge. Disclose any involvement in development.
2. Follow [setup and training](setup-and-training.md) on unrelated synthetic data. Keep training
   separate from measurements on the pilot task.
3. Complete [private intake and task freeze](intake-and-freeze.md). Select a
   [task card](task-cards.md) and agree a common output contract before either comparison arm.
4. Prepare a private session directory and use [measurement instructions](measurement.md).
5. Run the task, log all assistance and failures, obtain the actual operator/reviewer attestations,
   and complete the existing pilot record. Use [report and closeout](report-and-closeout.md).

Codex can prepare tooling and support execution. The operator does the work and the reviewer
makes decisions. Automated demo approvals, blank forms, elapsed tool time and repository ownership
cannot establish human participation, consent, acceptance or independence.

**Preparation proof is separate from pilot evidence.**

The [setup verification](../evidence/pilot-kit-setup-20260928.json) records an automated isolated
install, fixture generation and demo at the pinned baseline. It proves that setup path on the
recorded environment, not a new user's usability or performance. Subsequent application changes
need their own baseline. Timing-tool tests use synthetic records only.

If no participant is available, leave the pilot unexecuted. If no operating dataset is authorized,
a real person can perform a narrower synthetic/public-data usability task with that limitation
recorded. Do not relabel it a customer pilot or invent a manual comparison.

**Optional recruitment draft for Alex to send:**

> I'm testing a local data-onboarding portfolio project and would value an independent operator's
> feedback. The proposed exercise uses an agreed, authorized extract (or synthetic data), with a
> short training task followed by a bounded task and separate review. We would record setup and
> review effort, corrections and any help needed. Participation is voluntary; no employer or
> private data should be used without permission. Any public summary or quote needs separate
> approval. Could we first discuss whether the task and time commitment fit?

This is a draft, not a sent message or an agreement. Arrange the actual time commitment after
selecting the task. Do not request credentials or private extracts in public channels.
