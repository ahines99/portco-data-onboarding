# Report and closeout

Retain raw intervals, notes, fingerprints, outputs and decisions privately. The operator confirms
their effort and assistance log; the reviewer signs their assessment; the data owner separately
approves any sharing and retention/deletion. None of these attestations is generated by the tool.

Complete `pilot.json` using the existing [protocol](../OPERATOR-PILOT.md). Preserve nulls for missing
measurements, include every started attempt, and distinguish failed elapsed time from successful
completion time. Explain non-comparable tasks instead of forcing a paired savings calculation.

Draft an aggregate report containing:

1. Task scope, source class, date, software/environment and participant roles/relationships.
2. Authorization and disclosure status using opaque private references.
3. Comparison design, order, training, time cap and expected outputs.
4. Every task outcome, including unsupported, failed and withdrawn attempts.
5. Operator/reviewer/setup time separately, corrections, assistance and review cycles.
6. Correctness by mappings, units, joins and agreed metrics; denominator and missing decisions.
7. Publication/audit verification only for tasks that actually reached that stage.
8. Deviations, limitations, learning effects and useful changes suggested by observations.
9. Actual participant attestations and the separately authorized public scope.

Only compare matched completed tasks at the same scope. A percentage is descriptive of those
observations, not a general productivity guarantee. Do not extrapolate annual ROI from one operator.
No public result is required if the owner withholds sharing; preserve the private outcome instead.

Inspect the approved public report for sensitive paths, identifiers, quotations and small groups.
Publish only the permitted aggregate content under `docs/evidence/operator-pilot/`; do not copy
the entire private directory. Record the agreed retention or deletion action for source data,
snapshots and backups. Deletion of pilot data must not accidentally remove unrelated repository data.

Use observed friction to prioritize a connector or review-interface change. Preserve the original
attempt when testing a fix and disclose repeat-user learning. An unsuccessful result is evidence,
not a reason to invent a successful pilot or suppress its assistance burden.
